# 安卓运行位置与推荐环境讨论（2026-11-17）

安卓首版源代码已在 2026-11-17 开始落地，但仍需用户手机上的 Termux / Agent CLI / 网关真机验收。

## 产品方向

延续 Mac/Windows 各自在本机执行 Agent 的设计，安卓同时考虑两类执行位置：手机本地，以及用户自己的 Mac、Windows 或 Linux 服务器。网关配置决定模型请求发往哪里；执行位置决定命令、文件与 Agent 进程运行在哪里。两者分别选择。

本地模式中的 Agent、Git、编译命令和项目文件在手机；模型仍可通过所选网关调用。若该网关仍部署在 Mac 上，该 Mac 仍需在线。远程模式需要额外的安全会话服务或 SSH 适配，当前网关本身不提供桌面 PTY 恢复能力。

## Termux 推荐基线

- 首版候选：官方 GitHub 发布的 Termux `v0.118.3` 稳定版，优先 ARM64 安卓设备。官方将 `v0.119.0-beta.3` 标为 prerelease，不作为首版默认。
- 版本和来源一起管理。Termux 主程序与插件使用相同来源和兼容签名；不混用 F-Droid、GitHub、Google Play 或第三方修改版。
- 识别现有安装后再决定是否调整。不自动卸载，不因来源不同就清空用户已有环境。
- 手机首次设置应提供明确推荐组合与健康状态，记录 APK 版本、来源与校验值、Linux rootfs 版本或 digest、必要包清单、CLI 版本。不能仅锁 APK 后默认其余环境一致。
- 该组合尚未在用户设备测试。Android 版本、机型、子进程、工具权限及后台运行等验证通过后，才可标成工作台认证环境。

Android 0.1.1 提供手机本地 Termux PTY 与 SSH 电脑入口：调用配置加密保存、模型只读列表、收藏筛选、独立终端、全屏、Shell 保留和 Claude/Codex 独立配置。连接桥仅监听回环地址，访问需随机 token；上游调用 Key 不进命令行、不写明文配置。已在 Android API 34 模拟器安装并打开，检查工作区和 SSH 电脑表单；Termux 与真实手机网络链路尚未验收。

Termux 桥接设置需用户在 Termux 界面执行：`pkg install python bash git openssh`，然后显式启用 `allow-external-apps=true` 并重新载入设置，再授权工作台的 Termux 执行权限。Claude/Codex CLI 不是由 APK 偷装或打包；用户需要先在 Termux 配置。Claude 登录/模型兼容性和 Codex Linux API-key 自托管模式都要真机验证后，才可声称完整兼容。

用户确认 Windows 已连入当前网络。Android 0.1.1 已增加基于 Termux OpenSSH 的远程 shell 入口：可保存电脑地址、用户名、端口，在手机内嵌终端新开 SSH 登录。手机 Key 不发送给远端；目标电脑的 SSH 主机指纹由 Termux 确认。该入口不附着 Windows 工作台已存在的终端，也不自动转发 Windows 的网关或凭据。Mac/Windows 桌面工作台的有认证 PTY 会话服务仍未实现；CCHP 网关本身不是 PTY 服务。

## Linux 用户空间与虚拟机

Termux 提供 Android 上的 Linux 用户环境；PRoot 可运行 Linux 发行版用户空间，但仍共享 Android 内核，不等同于完整虚拟机。适合先探索现有 Git、Node、Python 及 Agent CLI 工具链；Codex 官方支持 macOS/Linux，不意味着官方承诺 Android/PRoot 兼容。

Android 官方还提供 AVF 路线，在支持的设备上运行 Debian VM 终端。完整虚拟机更接近独立 Linux 系统，但依赖具体设备及系统能力，不能作为所有安卓设备的通用前提。

建议先做一个经过真机验收的 Termux/Linux 用户空间适配，再评估 AVF 完整虚拟机适配；本地与远程复用任务配置和会话界面。暂不承诺在普通 Termux 中部署现有 CCHP Docker 栈。Agent 本地执行与模型本地推理是两个独立选项。

## 首次安装与零命令启动（2026-11-17 用户确认，待实现）

用户要求：安装完成后，在手机工作台点击 Codex 或 Claude 即可进入，日常使用不再输入安装、进入 Debian、连接桥接或启动 CLI 的命令。当前先继续平板上的手动安装验证，再实现简化引导；平板与手机分别检测和安装，不共享安装状态。

- 提供“安装本地 Agent”入口，可选择 Codex、Claude 或两者。自动检查现有 Termux、Linux 用户空间、Node.js 和 CLI，只补齐缺失部分，保留已有环境和项目。
- 安装展示阶段、下载进度、可理解的错误及重试入口；完成后检测真实版本与可启动性，不以下载完成或 APK 编译通过代替运行验收。
- 首次安装保留必要的 Android 安装确认、Termux 外部命令设置及执行授权；现成 Termux 的私有配置不能由工作台越权修改。自动引导不等于绕过系统授权。
- 安装后自动衔接 Debian 内 CLI 与工作台启动器，正确传递项目目录、所选模型、独立配置及会话模式；不要求用户每次进入 Linux 或手打 claude/codex。密钥不得放入进程命令行。
- 重开工作台或重启设备后，自动检查并恢复可用连接；原进程若已终止须如实说明。不得为安装或重连随意重启桥接、杀死已有任务或创建重复终端。
- 日常从已保存的调用配置、模型和项目直接启动；首次安装检查仅查询版本和启动状态，不调用模型、不产生推理费用。
- 验收：在实际 Android/PRoot 环境完成一次安装后，退出重开工作台，分别点击 Codex、Claude 均可进入交互界面，全程无需再输入启动命令。内置运行环境/配套运行器作为后续方案单独评估。

## 安卓独立工作与文件互通（2026-11-17 用户补充，待实现）

目标用户可以完全在安卓设备上完成编程和 Agent 任务，无需为了使用工作台而启动电脑。用户希望接近电脑上的工作体验：环境和工具可按需下载，项目可管理，来自电脑的文件能方便地进入安卓 Linux 工作区。

用户进一步确认的交互方向：工作台提供一键准备 Debian、安装 Codex/Claude 和安装状态检测；首次必要授权后，环境准备、项目文件、终端、模型配置及日常操作尽量都留在工作台完成。Termux 作为后台运行底座，用户通常无需打开其界面；当前实现仍依赖其进程、工具与 PTY 承载，不将界面隐藏误称为已经移除 Termux 运行依赖。

- 首版统一以 Debian 为默认和主要支持的 Linux 用户空间，普通安装引导不让用户选择发行版；检测、安装、启动及排错围绕同一套经过验证的环境。保留已有用户数据，不强制卸载或覆盖其他现有环境。
- 当前 Termux + PRoot 的 Debian 是共享 Android 内核的 Linux 用户空间，不宣传成完整虚拟机。支持设备上的 AVF/真正虚拟机作为后续运行后端评估，不作为普通安卓用户的使用前提。
- 本地终端、项目文件、CLI 和构建工具在安卓上运行；模型可连接用户自己选择的可访问网关。除非主动选择电脑上的网关或远程执行，否则不要求 Mac/Windows 保持开机。
- 提供持久的 Linux 项目目录，工作台选择项目后自动绑定到 Debian 内相同位置；重进应用、重新启动环境后文件与项目选择仍可找到。
- 优先提供 Android 系统文件选择器导入文件/文件夹/项目 ZIP，以及导出结果。电脑经 USB 文件传输或网盘把文件放入安卓“下载”等公共目录后，用户可在工作台选择并导入 Linux 工作区；不要求用户寻找容器内部隐藏路径或手写复制命令。
- Android 的 content URI 不能直接当成 Linux 路径。通过授权后的文件读取和现有本机桥接完成复制或映射，显示目标目录、传输进度及重名处理；保留现有文件。Git 工作区优先放 Linux 私有目录，避免公共存储不支持符号链接/权限语义造成兼容问题。
- 后续可增加 Git 仓库导入、SFTP/局域网传输等入口，复用工作区管理；首次文件互通不强制用户部署额外服务器。
- 验收路径：电脑传来一个项目文件夹或 ZIP → 安卓工作台导入 → 选择项目 → 点击 Codex/Claude → 在同一项目中工作 → 将修改结果导出给电脑。首次环境准备完成后，整条日常流程无需进入 Termux 手动执行命令。

## 0.1.7 实现与验收进展（2026-11-17）

已实现环境页一键检查并补齐 Termux 依赖、Debian、Node 与两种 CLI；安装阶段/日志持久化，重复请求加锁，运行中的安装使用独立脚本快照，失败保留数据与重试入口。升级桥接为新端口保留旧会话，回前台重连与一次自动启动桥接；进程已死亡会如实提示，不伪造恢复。

Agent 默认以 Debian workbench 普通用户启动，项目同路径绑定、配置分离，一次性私有文件交接环境后删除，退出 Agent 保留 Debian Shell 并清除凭据。Claude 使用明确 API Key 的 --bare 模式，显式提供项目上下文；自动记忆/插件同步等 bare 模式限制已在 Android README 说明。

真机：小米平板 5 Pro 12.4 + Termux 0.118.3 + PRoot-Distro 5.10.3 + Debian trixie，补齐缺失 Python 并验证普通用户下 Node 22.23.5、Codex 0.169.0、Claude 2.1.326。两种真实 CLI 已通过设备回环模拟网关测试认证、模型、Responses/Messages 与返回 Shell；未调用真实模型。

新增实际发现：Codex Linux 沙箱在此 PRoot 环境执行简单命令退出 182，关闭这层沙箱的对照成功。提供默认关闭、明确确认的命令兼容选项，保留 按需审批，不自动关闭审批或将容器宣称为安全沙箱。

仍需验收：全新 Termux 无 Debian 的完整下载路径、真实网关配置与模型对话、真机长期后台行为及文件导入/导出。以上完成项取代前文历史记录中对应“待实现”状态，不代表其余目标已完成。
