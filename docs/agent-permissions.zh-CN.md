# 权限与工具能力

首次启动会显示「Agent 权限设置」。macOS、Windows 的侧栏和 Android 顶部都有常驻入口。升级旧版本也需确认一次；取消设置不会偷偷放宽权限。本地 Agent 启动前会再次提示。系统 CLI 和 SSH 可以继续按外部设置运行。

## 推荐设置

| 客户端 | 推荐模式 | 需要更多权限时 |
| --- | --- | --- |
| Codex | 保留 workspace-write，允许联网，on-request 按需审批 | 项目外写入等操作由 Codex 申请；模型需要实际发起申请，工作台不能代替模型决定 |
| Claude | default 标准审批 | 命令、文件和网络操作按 Claude 自身规则确认；不能把 Codex 的文件沙箱规则套在 Claude 上 |

「允许联网」是一项通用设置，涵盖普通网络请求、Git 和下载依赖，不为单独的网站提供特殊授权。它不授予项目外写入权限；例如安装到系统目录仍可能需要再次授权。Codex 的项目模式通常可读取项目外文件，默认也允许写入临时目录，不等于文件只能在项目内被读取。

工作台保留启动环境中已有的 HTTP_PROXY、HTTPS_PROXY、ALL_PROXY 及其小写形式，并合并用户的 NO_PROXY 与本地回环地址，供两个客户端使用。macOS 不再清除 Claude 的代理；Android 将 Termux 的这组代理变量通过私有启动文件传入 Debian。图形应用能继承的环境与普通终端可能不同，未配置的代理不会凭空产生。Linux VM 与 SSH 使用各自环境的网络配置，手机的回环代理不会直接套给远端。

Codex 的「完整访问」使用 danger-full-access 和 on-request：关闭文件/网络沙箱，普通命令可直接运行，不保证逐条确认。Claude 的「跳过工具权限确认」使用 bypassPermissions，跳过工具权限检查。首次提高任一客户端权限须勾选明确确认。两者仍受当前登录用户与系统权限控制，不等于 root 或管理员。

设置通过启动参数应用到之后新建、恢复和分支的工作台会话；历史配置、Key、会话 ID 和外部客户端配置不会因权限选择而被重写。运行中的终端保留启动时权限，终端显示的标签也是启动时的实际模式。系统 CLI 沿用自身设置。

## 系统授权

macOS 的隐私目录、屏幕录制、辅助功能，以及 Windows 的管理员/UAC 授权，由系统在实际访问或启用相应能力时处理。安装工作台不能一次性替用户授予所有系统权限，也不需要把整个工作台默认以管理员身份运行。Codex 沙箱的实际实现与可用性由所安装的 CLI 和平台决定；工作台传入模式，不能代替 Windows 沙箱初始化或系统批准。

macOS 工作台启动后会先读取两个客户端的已保存工具配置，在加载模型列表和用量前检查屏幕录制状态。只要任一客户端已启用内置屏幕读取，工作台就会在缺少授权时提示状态，并在授权完成前阻止该客户端的新建、恢复和远程接续会话。首次检查可以由用户在工具页主动请求系统确认，后续启动只检查状态，避免反复弹窗。系统设置里的授权仍必须由用户确认，工作台不能静默写入 TCC。取消工具设置不会留下未保存的屏幕读取要求。

屏幕录制授权只解决系统能否生成截图。非官方模型、兼容网关或 Harness 还必须接受 MCP 工具调用和 PNG 图片内容，工作台无法替上游补齐这两项能力。此类请求失败时应先看网关返回的工具/图片兼容错误，再判断是否需要重新检查 macOS 权限；工具设置页也会明确显示这两个状态彼此独立。

Android 无 root。Debian 的 Codex 兼容模式如已启用，会关闭 Codex 沙箱并保留按需审批；可操作 Termux 和绑定给 Debian 的文件。Linux VM 内的 Codex 保持来宾完整访问和按需审批，以支持系统任务与 Docker，手机只暴露已共享的项目。Claude 权限选择作用于相应 Debian/VM 内。SSH 使用电脑的账号、文件与客户端权限。Termux 和文件访问需要 Android 自身授权。

## 桌面端拥有的能力，如何接到工作台

当前 Codex 桌面会话由宿主提供多种工具。下表区分权限和工具，不能把允许联网理解为已安装浏览器、技能或应用连接器。

| 能力 | 工作台现状 | 通用接入方式 |
| --- | --- | --- |
| 终端、命令、文件、联网 | CLI 原生工具，权限可在工作台设置 | 使用当前运行环境的 CLI 与按需审批；系统授权由系统处理 |
| 项目外目录 | Codex 沙箱写入受限，Claude 遵循自身规则 | 按需授权或客户端原生附加目录；如选择完整访问，界面明确显示 |
| 原生网页搜索 | 与 shell 联网不同，依赖客户端和上游 API | Codex --search 要求 Responses web_search；第三方模型或网关需验证，不默认开启 |
| 浏览器与系统图形操作 | 桌面端提供可选的主屏幕读取；其他控制可接兼容 MCP | 按需系统授权，模型须支持图片；浏览器与鼠标键盘控制另接工具 |
| Skills 与插件 | 可选择单个技能或 Claude 插件目录导入私有副本，默认停用 | 列表启停；Claude 最小模式主要通过 /命令调用技能，hooks 等能力仍受 CLI 限制 |
| MCP 服务 | 工具入口分别管理两客户端的服务配置，替代无条件空 MCP | 仅导入服务字段，不合并整个外部配置或转移外部账号 token；依赖与授权需在当前环境准备 |
| Canva、Figma 等应用 | 属于已安装的宿主连接器，未自动接入工作台 | 使用相应兼容服务并由用户重新授权账号 |
| Codex 桌面线程、面板、工作树工具 | 桌面宿主专用 | 工作台提供自己的管理能力或使用公开接口，不能承诺原样迁移 |

权限和基础工具入口均已接入三端，详见[工具接入说明](tool-bridge.zh-CN.md)。完整插件兼容、依赖/连接状态探测、OAuth 和 Android 本机屏幕捕获仍跟踪于 [工具能力桥接 #12](https://github.com/Cass-ette/agent-workbench/issues/12)；登记工具不等于服务已连接或系统已授权。

## 连接失败如何判断

单独的 error connecting to api.github.com 不能证明是沙箱；还可能是网络、代理、DNS、登录或服务故障。先核对终端显示的权限，再比较普通终端中的同类只读请求。不要让模型把一次连接失败直接归因于没有管理员权限，也不要删除用户代理或外部认证来“修复”。

协议与配置依据：[Codex 官方配置 schema](https://github.com/openai/codex/blob/main/codex-rs/core/config.schema.json)、[Codex 安全与审批文档](https://developers.openai.com/codex/security)、客户端 codex --help 与 claude --help。
