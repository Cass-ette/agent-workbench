# 手机接续电脑工作台

本轮提供第一阶段测试实现：Android 通过已配对的 SSH 连接，控制 Mac / Windows 工作台内的同一个终端进程。电脑继续持有项目、Key、模型配置和 CLI 历史。手机本地的 Debian、Linux VM 和普通 SSH 仍独立保留。

## 使用

1. 两端都更新到包含本功能的测试版。在电脑开启系统 SSH 服务；在电脑工作台的「手机连接」勾选「允许通过 SSH 接续这台电脑的工作台」。
2. 复制连接码，在 Android「运行环境 → 添加电脑」粘贴。复制使用系统剪贴板，小米互联等跨设备剪贴板可能同步内容；连接码不含密码、私钥或工作台访问令牌。
3. Android 工作区选择这台电脑，点「连接电脑工作台」。首次连接在下方「电脑登录」终端完成 SSH 登录，再展开「配置任务」。已记住手机的账号可自动登录。
4. 在电脑运行列表点「接续并控制」，或选择电脑端的工作台配置 / 系统 CLI、项目目录后新建会话。电脑与手机看到的是同一会话；无需另起一份 Agent。
5. 「恢复最近对话」按电脑目录和客户端找原配置；全部项目历史按目录浏览。选择「从历史创建分支」才用当前电脑配置创建独立分支。无法确认历史是否被运行中的会话占用时，提示从运行列表接续，不强行抢锁。

## 断开、控制权与附件

- 手机关闭电脑会话标签只断开显示。「结束电脑任务」单独确认后停止电脑终端。电脑工作台退出、电脑关机/睡眠或系统停止进程时，任务无法继续，手机会失去连接。
- 手机掉线后重新连接，再选择原运行会话。原进程保持运行；不自动重试不确定是否执行的输入。最近 1 MiB 终端输出可回放，更早输出不保存在该回放缓存中，CLI 原有历史不受影响。
- 手机取得输入控制权后可发送文字、快捷键并处理 CLI 原生审批。电脑本地输入会收回控制；手机显示只读，需要时再次点「接续并控制」。系统隐私弹窗/UAC 仍须在电脑端完成。
- 「传文件/图片」读取用户选择的文件，分段传到电脑私有附件目录，完整接收后插入对应电脑路径，不自动回车。单个附件上限 20 MB；切换会话取消插入。附件保留给之后恢复历史使用，手动删除会让历史中的路径失效。
- 工作台服务只监听电脑回环地址，访问凭据保存在电脑当前账号的私有位置。SSH 登录后的助手在电脑本地使用凭据；凭据不会写进连接码或返回手机。本地请求强制不经过系统 HTTP 代理。

## 本轮边界

- 当前接续对象是启用此服务的新版电脑工作台内终端。旧版应用或外部终端中已运行的进程不会被自动接管；普通 SSH 主机继续使用「普通 SSH」。
- 工具和权限沿用电脑会话。修改电脑 MCP/Skills/插件、增删 Key、账单管理以及系统授权面板仍在电脑端完成，本轮未把整套设置面板搬到手机。手机本地工具和权限按钮明确标为「本地」。
- 终端 UI 是 CLI 的原生交互，尚无独立的结构化审批面板。执行位置为电脑时，截图工具看到的是电脑屏幕；不能据此读取手机屏幕。
- 已实现自动化协议、权限边界、附件和共享 PTY 测试；真实手机到 Mac/Windows 的 SSH、两端同时操作、手机后台和网络切换仍须实机验收，不能把编译通过当成这些场景已经验收。
- 两个独立 Agent 的任务派发与协作留在 [#18](https://github.com/Cass-ette/claude-cchp-manager/issues/18)。本轮及后续接续工作见 [#19](https://github.com/Cass-ette/claude-cchp-manager/issues/19)。
